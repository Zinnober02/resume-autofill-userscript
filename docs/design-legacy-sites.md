# 面向老旧招聘站点的兼容策略（央国企场景）

> 背景：央国企招聘站点技术栈老旧且毫无规范——jQuery / AngularJS 1.x / 服务端直出，手写 CSS，不用 Element / Ant Design 等组件库；页面结构混乱，字段信息有的写在标签属性里、有的写在 value 里，缺乏一致性。
> 典型样本：中国电信招聘（`.scratch/telecom/page-0.html`）——AngularJS 1.x + jQuery + bootstrap-select + 手写 `dy-form` 指令，字段名塞在 `msg` 属性里，id 是 `11_245_1` 这种无语义编号。
>
> 核心结论：**「为每个站写适配」是死路。正确的思路是把填充拆成识别、操控、反馈三层，每层都用「多信号融合 + 策略链降级 + 写后验证」来消化不确定性。**

## 一、识别层：从「规则匹配」升级为「信号打分」

现在的 `src/core/rules.js` 是「label 文本 → 正则 → 命中字段 key」的单信号模式。老站的问题是标签可能出现在任何地方，单信号一旦缺失就整个识别失败。改成信号融合。

### 信号源清单（按可信度大致排序）

1. **控件自身属性**：`msg`（电信就是）、`title`、`placeholder`、`name` / `id`、`data-*`、`value`（有些站把说明写进 value）。
2. **结构上下文**：`label[for]`、父格子的兄弟文本（现有 `labelText` 已覆盖）、**表格上下文**——`<td>` 对应的行头和列头 `<th>`（家庭关系、教育经历这种表格布局，「姓名」往往只在 `<thead>` 里出现一次）、`fieldset > legend`、`dt/dd` 对。
3. **空间邻近**：浏览器里用 `getBoundingClientRect` 找控件左方/上方最近的可见文本节点兜底（jsdom 测试里打桩即可，现有测试基建已经这么做）。
4. **内容反推**：`regionLevelOf` 已验证这个思路——下拉的选项内容本身就是强信号（一堆省名就是省份框，「男/女」就是性别框，不管标签写没写）。可推广到学历、政治面貌、婚姻状况等有穷枚举字段。

### 打分而不是硬匹配

每个信号源给出候选 key 和权重，加权求和，设三档阈值：

- **高置信**：直接填；
- **中置信**：填，但在报告里标黄「不太确定，请检查」；
- **低置信**：不填，记入 unknown。

关键原则：**宁缺毋滥**。混乱站点上填错比不填更糟——把「姓名」填进家庭关系表的「父亲姓名」格，用户就得逐个字段检查清错，工具就失去意义了。现有的 `neg` 否决词和 `ctx` 区块上下文（`sectionBlockType` 的栏内投票）保留，纳入打分体系作为正负权重。

## 二、操控层：行为探测的 driver 注册表 + 写后验证

### driver 注册表

每种控件形态一个 driver，统一接口 `canHandle(el) / setValue(el, value) / verify(el)`。识别不靠类名硬编码，靠行为特征探测：

- 点开出现浮层 → 浮层类 driver（现有 `floating-picker` 的「新出现的浮层 + 同构子元素组」识别就是这个思路，推广它）；
- 存在可见镜像代理（按钮/展示框）而原生控件被隐藏 → 镜像驱动；
- 什么都没有 → 原生 `setVal`。

央国企老站的高频形态值得各配一个 driver：jQuery UI（datepicker / autocomplete / selectmenu）、easyui combobox、**layui**（政府国企站极常见，select 渲染成 `dl/dd` 镜像）、select2 / chosen / bootstrap-select（已有）。识别依然走行为而非类名，比如「原生 select 被隐藏，紧邻一个同尺寸可点击的 div」。

### 事件全套餐

老框架监听的钩子五花八门——AngularJS 听 `change`，jQuery 校验常挂 `blur`，更老的挂 `keyup` 甚至 `propertychange`。`setVal`（`src/core/form-control.js`）目前只派 `input + change`，应扩展为 `focus → input → keyup → change → blur` 的完整序列，模拟真人操作的事件轨迹。成本极低，兼容收益大。

### 写后验证（当前的关键缺失）

每个 driver 写完必须读回验证——原生 value 非占位、镜像文本更新、或框架状态类变化（如 `ng-empty → ng-not-empty`）。验证失败降级到下一个 driver 重试；全部失败记 manual。老站常见「值写进去了但校验不认」（blur 时清空非法值），没有读回验证就永远发现不了。

## 三、反馈层：把「适配新站」变成低成本的固定动作

代码再通用也追不上全网站点，要设计好「遇到新站怎么办」的闭环：

1. **现场报告**：现有 filled / manual / unknown 报告是基础，增强为——每个 unknown 控件附带「脚本看到的全部信号」（各信号源分别读到了什么文本），让用户一眼知道该补哪条规则。
2. **用户规则沉淀**：`matchExtra` 已是这个出口，把它从「当前资料的一次性补丁」升级为**按站点（host）持久化的规则包**。规则包严格隔离在通用引擎之外——引擎永远不含 `chinatelecom.com.cn` 这种特判。
3. **调试模式**：面板上加「检查控件」功能，点一下页面控件就显示识别结果和信号明细，把写规则的门槛降到非技术用户可用。
4. **快照语料库**：每搞定一个新站，把问题片段抽成精简 fixture 进 `tests/fixtures/`。积累几十个站后，这个语料库就是「泛化性」的实证——每次改引擎跑全量 fixture，保证新加的适配不破坏旧的。

## 四、老站特有的坑和对策清单

| 坑 | 对策 |
| --- | --- |
| iframe 套 iframe | 现有 `src/core/messaging.js` 跨框架协议已覆盖，注意 `@match` 要允许注入子框架 |
| `<table>` 当表单容器 | 识别层的表格上下文信号（th/td 行列头） |
| GBK 编码 / 全角字符 | `norm()` 的全角转半角已处理，注意全角数字、全角冒号混在标签里 |
| onblur 才校验 | 事件全套餐覆盖 |
| 提交前才渲染的分步表单 | `src/core/watcher.js` 的 MutationObserver 重填已覆盖 |
| 验证码、文件上传、照片裁剪 | 明确划为 manual 范围，不碰 |

## 五、明确不做的事

- 主引擎里**永不出现 URL / 域名特判**（站点差异只能进用户规则包）；
- 不靠组件库类名做唯一判据（类名是线索不是依据，依据是行为）；
- 不为了提高「填充率」数字而降低置信度阈值——错填的代价远大于留空。

## 六、落地顺序

1. 事件全套餐 + 写后验证（改动小，对所有站点立刻生效）；
2. `labelText` 扩展表格上下文（th/td、fieldset/legend）+ 信号打分重构；
3. driver 注册表化（把现有 search-select / floating-picker / custom-select 收编进统一接口）；
4. layui / easyui / jQuery UI 的行为探测 driver（央国企覆盖率大头）；
5. 站点规则包持久化 + 调试模式；
6. 快照语料库随用随攒。

一句话总结：**对不确定性分层消化——识别靠信号融合，操控靠策略降级，覆盖率靠用户规则沉淀，泛化性靠快照回归证明。**
